# v0.1.0 — 最小端到端闭环

第一个可运行版本。提问进来，按时间范围检索时间线记录，组装成带来源的上下文，交给模型生成回答，以 SSE 流式返回。

## 这个版本包含什么

| 模块 | 内容 |
|---|---|
| 1 项目骨架 | Spring Boot 4.0.8 / Java 21、统一响应与异常、健康接口真实探活数据库 |
| 2 时间线 | `timeline_entry` 增删改查、软删、`end_time` 为空表示进行中、时间重叠查询 |
| 3 AI 接入 | DeepSeek 主备模型、SSE 流式、Qwen embedding、失败降级 |
| 4 最小闭环 | 时间窗解析、关键词抽取、检索回退、预算组装、来源与正文一一对应 |

## 接口

- `POST /api/chat` — 同步返回 `ApiResponse<ChatAnswerResponse>`
- `POST /api/chat/stream` — SSE，事件顺序固定为 `start → sources → delta* → done`，失败时为 `error`（带 `partial` 标记）
- 时间线增删改查与 `/api/health`

流式与非流式共用同一次「检索 + 组装」，区别只在最后一步是转发 SSE 还是一次性返回。所有确定性失败（参数错误、未配置 key、数据库不可用）都发生在建立 SSE 之前，保留 HTTP 语义；进入流之后的失败只能以 `event:error` 表达。

## 验证

- 非集成测试 120 个通过，Testcontainers 集成测试 15 个通过
- 本机实测：未配置 key 返回 503 且不查库；真实模型调用为 `start → sources(3) → delta* → done`；无命中时不编造记录；停库返回 503；客户端取消后不再产生 `delta`/`done`

完整结果见 `docs/verification/04-closed-loop.md`。

## 已知限制

- 单轮无状态，不建会话表，不支持追问
- 只有一个知识源（时间线），文档、图谱、记忆尚未接入
- 时间解析是规则实现，关键词抽取只覆盖引号短语与 ASCII 词
- 无前端，只能通过 curl 或接口工具调用
- 上游真实断流的 `partial` 分支沿用模块三单测，本版本未重复实测

## 运行

需要 JDK 21、Maven、Docker。数据库与 pgvector 由 `docker-compose.yml` 提供。

```bash
docker compose up -d
export DEEPSEEK_API_KEY=...
export DASHSCOPE_API_KEY=...
mvn spring-boot:run
```
